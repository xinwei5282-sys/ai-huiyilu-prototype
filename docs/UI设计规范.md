# 云忆回忆录 UI 设计规范（Design Foundation）

> 本文件是云忆回忆录原型的唯一视觉设计真源。颜色、排版、间距、组件样式、页面模式和适老要求均以本文件为准；当前实现以 `prototype-v17.html` 对照，产品边界以项目 `AGENTS.md` 为准。

**适用范围**：高保真原型、客户演示图、后续移动端设计与前端实现
**基准设备**：390px、414px、430px 宽移动屏
**最后整理**：2026-07-30

---

## 1. 品牌定位与设计原则

### 1.1 产品定位

云忆帮助长辈和家人轻松讲述生命经历，并把零散讲述逐步沉淀为故事、章节和成书成果。

核心气质：

- **温暖**：像家人陪在身边，不像冷冰冰的工具。
- **安静**：内容是主角，装饰和动效保持克制。
- **低压力**：鼓励慢慢讲，不强化题量、进度和未完成负担。
- **有陪伴感**：反馈使用自然、安心的表达，明确告诉用户内容没有丢。
- **有成果感**：故事、章节、书籍和分享结果应被认真呈现。

视觉关键词：暖阳、书页、相册、陶土、木色、家庭记忆。

避免：任务后台感、促销感、冷科技感、养老院式厚重感、通用白卡堆叠。

### 1.2 五条设计原则

1. **先让人开口，再展示功能**：讲述页一屏一焦点，录音是第一操作。
2. **成果比进度重要**：书房先展示完成章节，未完成事项归入“我的”。
3. **适老不是放大版普通 UI**：减少输入、降低层级、增强对比、强化容错。
4. **情绪材质服务内容**：纸页、书籍、照片只增强记忆感，不妨碍阅读。
5. **状态必须被看懂**：不能仅靠颜色区分，必须配合文字、图标或形态。

## 2. Design Tokens

### 2.1 颜色

#### 基础与文字

| Token | 标准值 | 语义与用途 |
|---|---:|---|
| `--cream` | `#FAF6F0` | 页面默认暖奶油背景 |
| `--cream-2` | `#FFFBF5` | 纸页白、输入区、次按钮 |
| `--card` | `#FFFFFF` | 浮层和需要清晰分离的内容面板，不作整页底色 |
| `--brown-h` | `#1E1712` | 大标题、核心提问、重要成果标题 |
| `--brown` / `--text` | `#2A2019` | 正文、列表标题、主要信息 |
| `--brown-500` | `#8A6F5C` | 暖棕说明、次级标题 |
| `--text-2` | `#7C6B5E` | 次级正文、辅助说明 |
| `--text-3` | `#746456` | 时间、占位、非关键提示；当前采用较深值保障适老对比 |
| `--paper-line` | `#EFE1D2` | 纸页与输入控件边界 |
| `--line` | `#EDE4D8` | 列表分隔和轻边框 |

#### 品牌与行动

| Token | 标准值 | 语义与用途 |
|---|---:|---|
| `--gold` | `#D9663F` | 陶土橙；品牌强调、当前进度、关键图标 |
| `--gold-deep` / `--gold-ink` | `#B44A2A` | 链接、选中态、暖底强调文字 |
| `--gold-btn1` | `#C45331` | 强行动按钮渐变起点，保证白字对比 |
| `--gold-btn2` | `#A83F27` | 强行动按钮渐变终点，满足白字对比 |
| `--green` / `--success` | `#4C7A5C` | 已保存、已完成、已采纳、安心继续 |
| `--green-700` | `#3C6249` | 成功状态深色文字 |
| `--success-bg` | `#E7F0E8` | 成功浅底 |
| `--progress` | `#D9663F` | 录音、处理中、当前进度 |
| `--progress-bg` | `#FDE7D6` | 进度浅底 |
| `--danger` | `#B23A2E` | 删除、错误、不可逆操作 |
| `--danger-bg` | `#F6E1DA` | 危险浅底 |
| `--info` | `#4E6E78` | 网络、权限和系统类中性信息 |
| `--info-bg` | `#DCE7E8` | 中性信息浅底 |

#### 用色比例与边界

- 约 **60%** 暖奶油和纸页底色，**30%** 深棕文字与木色结构，**10%** 陶土和松绿强调。
- 陶土色用于行动和当前状态，不在同一页面制造多个同级强按钮。
- 松绿只表达完成、保存、采纳和安心反馈，不与主 CTA 竞争。
- 红色只表达错误、危险和不可逆操作，不用于普通进度。
- 不使用科技蓝紫作为品牌主色；蓝灰只用于中性系统信息。
- 任何新增色值必须先命名、定义语义，再进入页面样式。

### 2.2 排版

#### 字体栈

```css
--sans: "PingFang SC", "Noto Sans SC", -apple-system, BlinkMacSystemFont, sans-serif;
--serif: "Noto Serif SC", "Songti SC", serif;
```

- 界面、按钮和辅助信息使用 `--sans`，保证移动端清晰度。
- 故事标题、章节名、金句和书页正文可使用 `--serif`，强化出版物气质。
- 一般列表不要为装饰而使用衬线体。
- 数字进度使用等宽数字特性 `font-variant-numeric: tabular-nums`。

#### 字阶

| Token / 用途 | 字号 | 推荐行高 | 字重 |
|---|---:|---:|---:|
| `--fs-sm` / 辅助信息 | 14px | 1.5 | 400–600 |
| `--fs-md` / 正文与按钮 | 16px | 1.6 | 400–600 |
| 核心提问、长篇阅读 | 18px | 1.75–1.9 | 400–600 |
| `--fs-lg` / 分区标题 | 20px | 1.4 | 600 |
| `--fs-xl` / 页面标题 | 24px | 1.3 | 600 |
| 情绪型首页标题 | 34–42px | 1.05–1.15 | 700–900 |

适老底线：关键正文不小于 16px，辅助文字不小于 14px；11–12px 仅允许用于原型开发标记或非关键角标，不进入长辈主流程。

### 2.3 间距与布局

使用 4px 基础单位，避免每个模块随意定义间距。

| Token | 值 | 用途 |
|---|---:|---|
| `space-1` | 4px | 图标内部、紧邻信息 |
| `space-2` | 8px | 标签、控件内部小间距 |
| `space-3` | 12px | 同组元素默认间距 |
| `space-4` | 16px | 页面左右边距、卡片内边距 |
| `space-5` | 20px | 重要组件内边距 |
| `space-6` | 24px | 内容分组间距 |
| `space-8` | 32px | 页面大段落与情绪留白 |

布局规则：

- 移动端页面默认左右边距 16px；沉浸照片区可延伸到屏幕边缘，但文字必须回到安全内容区。
- 同一内容组内部使用 8–12px，组与组之间使用 20–32px，形成“紧组、松段”的节奏。
- 一屏只设置一个主焦点和一个主 CTA。
- 底部固定操作需叠加 `env(safe-area-inset-bottom)`，不得遮挡正文或系统手势区。
- 顶部内容避开状态栏和微信胶囊；二级页保留清晰返回路径。

### 2.4 圆角

| Token | 值 | 用途 |
|---|---:|---|
| `--r-sm` | 8px | 小标签、轻按钮、输入控件 |
| `--r-md` | 12px | 标准按钮、提示和小卡片 |
| `--r-lg` | 16px | 内容卡、录音面板 |
| `--r-xl` | 20px | 情绪型大卡、首页主要入口 |
| `--r-pill` | 999px | 胶囊标签、录音状态、头像 |

圆角表达亲和，不代表所有内容都要包成圆角卡片。书籍封面可以使用更克制的 5–12px 圆角，保留实体书形态。

### 2.5 阴影与层级

```css
--sh-1: 0 4px 14px -8px rgba(150, 74, 42, .22);
--sh-2: 0 8px 24px -14px rgba(150, 74, 42, .30);
--sh-3: 0 24px 50px -26px rgba(150, 74, 42, .42);
--sh-mic: 0 16px 30px -12px rgba(180, 74, 42, .55),
          inset 0 1px 0 rgba(255, 255, 255, .45);
```

- `--sh-1`：列表浮起、轻入口。
- `--sh-2`：成果卡、主要内容面板。
- `--sh-3`：弹层和需要明显脱离背景的区域。
- `--sh-mic`：仅用于录音主控等高频核心动作。
- 阴影带暖棕色，不使用冷灰重阴影；边框和阴影择一强化，避免双重厚重。

### 2.6 动效

| 场景 | 时长 | 建议缓动 |
|---|---:|---|
| 按压和选中反馈 | 120–180ms | `ease-out` |
| 标签、提示、内容切换 | 180–260ms | `cubic-bezier(.2,.8,.2,1)` |
| 抽屉和底部弹层 | 260–340ms | `cubic-bezier(.2,.8,.2,1)` |

- 动效用于解释状态从哪里来、到哪里去，不作无意义循环装饰。
- 录音波形可以循环，但同时显示“录音中”和计时，不能只靠动画表达。
- 避免弹跳和弹性缓动；避免动画改变宽高、边距等导致布局抖动。
- 在 `prefers-reduced-motion: reduce` 下关闭装饰动效，并保留状态文字。

### 2.7 兼容与资源变量

`--home-bg`、`--brand`、`--bubble`、`--svc-bg`、`--session-paper`、`--session-scene` 是原型资源入口，不是颜色 token。资源替换必须保持相同语义和文字可读性。

`--A-*`、`--sh-card`、`--sh-soft` 是当前原型中的历史兼容别名，新设计和新代码不得继续扩散；后续改造时分别收敛到品牌 token、`--sh-2` 和 `--sh-1`。

## 3. 图像、材质与图标语言

### 3.1 摄影

- 使用自然暖光、真实家庭环境和生活化动作，人物表情自然，不采用棚拍宣传姿势。
- 长辈形象要有尊严和主体性，不以“被照护者”刻板呈现。
- 首页情绪图允许较大面积展示，但人物面部和核心操作不得互相遮挡。
- 图片上的文字必须叠加暖色遮罩、渐变或局部明暗控制，确保稳定可读。
- 禁止科技光效、蓝紫霓虹、过度磨皮和明显 AI 合成人像质感。

### 3.2 纸页、书籍与相册

- 纸页使用暖白、细分割线和浅暖阴影，纹理透明度要低。
- 故事卡强调阅读节奏，避免密集操作悬浮在正文上。
- 章节书本可使用书脊、封面层次和木架背景，但章节名称必须首先可读。
- 整本书入口是成果的次级入口，不做压住章节的重型 Hero。
- 相片使用克制白边或相册式留白，不使用灰色空图占位作为正式成果。

### 3.3 图标

- 采用轮廓清楚、语义直接的线面结合图标，视觉尺寸约 20–24px。
- 图标按钮点击热区仍需达到 44px；不能按图形本身大小计算热区。
- 录音、返回、关闭、上传和分享使用大众熟悉的符号，不创新隐藏手势。
- 图标不能代替关键文案；老人主路径的核心操作必须同时出现文字。

## 4. 核心组件规范

### 4.1 按钮

| 类型 | 外观 | 最小高度 | 使用场景 |
|---|---|---:|---|
| 主按钮 | 深陶土渐变、白字 | 52px | 开始录音、确认生成、最终提交 |
| 低压主入口 | 浅陶土纸感、深棕字 | 56px | “按问题慢慢讲”等默认主路径 |
| 次按钮 | `--cream-2`、轻边框、深棕字 | 48px | 跳过、稍后、切换方式 |
| 文字按钮 | 透明、`--gold-deep` | 44px 热区 | 查看、编辑、轻量导航 |
| 危险按钮 | `--danger-bg`、`--danger` | 48px | 删除、退出且不保存 |

规则：

- 同屏只保留一个视觉最强的主按钮。
- 按钮文字使用明确动词，如“开始讲述”“保存故事”，不使用模糊的“确定”。
- 按下态必须有亮度、位移或透明度反馈；加载态防止重复点击。
- 禁用态说明原因，不只变灰。

### 4.2 录音主控

- 放在页面下半部拇指易达区，建议高度不小于 56px。
- 待录音：陶土主按钮，文案“按住讲”或“开始讲述”。
- 录音中：显示录音文字、计时和波形；陶土进度色，不使用危险红。
- 暂停：状态明显变化，并提供“继续讲”和“结束本段”。
- 处理中：保持当前内容可见，说明正在整理且内容已保存。
- 权限失败：使用中性信息面板说明开启路径，保留键盘输入出口。
- 断网：明确“内容已保存在本机”，提供恢复和重试。

### 4.3 导航

- 主导航固定为“讲述 / 书房 / 我的”三栏，图标和文字同时出现。
- 底栏单项热区不小于 48px，高亮使用 `--gold-deep`，未选中使用 `--text-3`。
- 二级页顶部返回热区不小于 44px，标题居中或在返回后左对齐，但全项目保持一致。
- 临时、可取消的小任务使用底部弹层；有明确层级和可分享 URL 的内容使用页面跳转。

### 4.4 故事成果卡

- 内容顺序：故事标题 → 正文摘要或金句 → 图片 → 时间/来源 → 次级操作。
- 使用暖白纸页底和 `--sh-2`，正文优先，不在卡片顶部堆叠多个图标入口。
- 自动保存通过松绿文字或胶囊反馈，不打断阅读。
- 编辑、分享、收进书房属于次级动作，不能与阅读标题竞争。

### 4.5 章节书本与整本书入口

- 章节书本是书房第一视觉单位，展示章节名和已完成成果。
- 木架和封面色可形成变化，但文字对比必须稳定。
- 书房不展示“进行中”“还差多少题”等任务压力。
- 整本书使用顶部或分区标题旁的轻入口，不使用大面积重卡。

### 4.6 状态标签与提示

| 状态 | 颜色 | 必备文字 |
|---|---|---|
| 进行中 | `--progress-bg` + `--gold-deep` | “录音中”“正在整理” |
| 已完成 | `--success-bg` + `--green-700` | “已保存”“已成稿” |
| 待处理 | 暖奶油底 + `--brown-500` | “待家人确认”等具体状态 |
| 错误 | `--danger-bg` + `--danger` | 原因和可执行出口 |
| 系统信息 | `--info-bg` + `--info` | 权限、网络或系统说明 |

Toast 只用于短暂确认；需要用户处理的错误必须留在页面内，不能自动消失。

### 4.7 输入、照片上传与弹层

- 输入框正文不小于 16px，聚焦时边框使用陶土色并保证键盘不遮挡当前输入。
- 能选择就不强迫输入，能语音就不强迫打字。
- 上传前说明照片用途；上传中显示进度，失败保留原选择并提供重试。
- 底部弹层顶部圆角 20px，最大高度约 80vh，可滚动并避开底部安全区。
- 破坏性确认必须明确说明影响，并把取消作为易达操作。

### 4.8 空状态

- 空状态解释“这里会出现什么”，并给出一个明确下一步。
- 书房空态引导完成第一篇故事，不展示任务清单。
- 我的未完成列表为空时强调“都已整理妥当”，不制造焦虑。
- 空状态不使用大面积灰色占位或通用插画遮盖主要操作。

## 5. 关键页面模式

### 5.1 讲述页

- 唯一主任务是开口讲述；核心提问和录音主控必须在首屏可见。
- 语音、键盘、照片是三种输入方式，但只让当前方式成为主操作。
- 自动保存、暂停、处理中、断网恢复必须连续，不让用户怀疑内容丢失。
- 问题进度弱化展示，不用 `0/45` 等强任务数字占据首屏。

### 5.2 书房

- 定位为“已完成成果展示区”。
- 背景氛围 → 轻说明 → 章节成果书架 → 整本书轻入口。
- 不放参与中、未完成、中断内容，不放冗余记忆信息块。
- 视觉参考若与上述边界冲突，以产品边界为准。

### 5.3 我的

- 承接未完成事项、账户资料、家人协作和增强能力。
- 未完成内容给出明确“继续讲”入口，但不使用责备或倒计时语言。
- AI 人物形象是可选增强，不能阻断讲述、成稿或分享；生成后不自动替换头像。
- 危险操作和账号操作与高频主任务分组隔离。

### 5.4 分享与成果

- 分享卡、人物形象和章节封面最终都应引导进入一段真实故事或回忆提问。
- 视觉像家庭纪念品和出版物，不像营销海报。
- 分享预览不得出现灰块、空图和开发占位。
- AI 生成素材必须允许用户确认、更换或放弃，不能覆盖原始照片。

## 6. 状态、适老与无障碍

### 6.1 六类状态

每个核心流程必须覆盖：

1. **加载**：优先使用骨架或保留原内容，避免只显示转圈。
2. **空**：解释结果区域会出现什么，并提供下一步。
3. **错误**：说明原因、影响和可执行出口。
4. **断网**：说明本地保存情况，提供重试或稍后继续。
5. **成功**：使用松绿明确确认，不阻断下一步。
6. **恢复**：提示已找回的内容及继续位置。

### 6.2 手动适老模式专项规范

云忆提供可由用户手动开启的“适老模式”。基础模式仍需满足通用可读性和可访问性要求；开启适老模式后，在不改变内容、不删减核心功能的前提下，统一放大字号与热区、降低信息密度、强化操作反馈。

#### A. 开启入口与模式状态

- 入口名称固定为“适老模式”，不使用“老人模式”“老年版”等标签化名称。
- 入口放在“我的 → 设置”可直接找到的位置，使用“文字标签 + 开关”；整行热区不小于 56px。
- 开启前用一句话说明影响：“字体更大、按钮更清楚、操作更简单”。
- 切换后立即生效，不要求退出或重启；模式状态跨页面保持。
- 顶层导航和核心页面不持续展示模式徽章，避免给用户贴标签；设置页开关状态是唯一控制真源。
- 开启或关闭只改变视觉与交互呈现，不改变故事内容、账号数据、套餐和隐私权限。
- 如果页面无法完整适配放大后的内容，应允许自然滚动，不能通过截字或缩回小字号解决。

#### B. 视觉与阅读

| 项目 | 基础模式 | 适老模式 |
|---|---:|---:|
| 正文字号 | ≥16px | ≥18px，阅读正文建议 20px |
| 辅助文字 | ≥14px | ≥16px |
| 页面标题 | 24px | 28–32px |
| 行高 | ≥1.6 | 1.75–1.9 |
| 中文每行 | 18–24 字为宜 | 16–20 字为宜 |
| 文字对比 | ≥4.5:1 | 关键文字和操作建议 ≥7:1 |

- 不用浅灰、细字重和透明度降低来制造层级；改用字号、间距和位置。
- 标题与正文左对齐优先，长段正文禁止居中。
- 避免全大写英文、过宽字距和连续斜体；英文只作为非关键装饰。
- 适老模式的字号放大使用语义字号 token，不对整个页面做 CSS 比例缩放。
- 支持系统字号继续放大时，文字不截断，按钮和卡片随内容增高。
- 图片、纹理和光影不得穿过正文；文字在图片上时必须提供稳定遮罩。

#### C. 触控与拇指热区

- 适老模式普通点击热区不小于 56×56px；返回、关闭等操作不得低于 48×48px。
- 高频主操作建议 60–64px 高，放在屏幕下半部拇指易达区。
- 相邻可点击元素间净距不小于 8px，危险操作与主操作间距不小于 16px。
- 点击立即出现按下反馈；超过 300ms 的处理显示明确加载状态并防止重复提交。
- 不使用双击、长按、侧滑等隐藏手势作为唯一入口；手势必须有可见替代。
- 固定底栏叠加系统安全区，不能贴住 Home 指示条。

#### D. 认知负担与导航

- 一屏一个主任务、一个主 CTA；次级功能渐进展开。
- 保留“讲述 / 书房 / 我的”三栏，不因开启适老模式改变信息架构或入口位置。
- 同屏次要入口可以收进“更多”，但不能隐藏当前流程的退出、返回和替代输入方式。
- 操作名称使用生活化动词，如“继续讲”“保存故事”，避免“提交任务”“生成资产”等系统术语。
- 不要求用户记住上一步信息；在当前页面保留人物、章节和故事上下文。
- 不使用倒计时、连续签到、完成率排名和强题量数字制造压力。
- 二级页必须有明确返回；取消操作回到原状态，不让用户猜内容是否保存。

#### E. 输入与语音

- 语音是默认低负担输入，键盘和照片是并列替代出口。
- 开始录音前说明用途；录音中同时显示文字状态、计时和可暂停入口。
- 录音结束后先保留原音频，再进入转写或生成，不因处理失败丢失原始内容。
- 键盘弹起后输入区和主要操作保持可见；支持大字号下滚动到当前焦点。
- 表单能选则不输，能自动带入则不重复询问；每屏表单项尽量不超过 3 个。
- 权限失败必须提供逐步开启说明，并保留“改用文字输入”等替代路径。

#### F. 状态反馈与容错

- 保存、网络、权限和生成状态使用“发生了什么 + 内容是否安全 + 下一步做什么”的三段式信息。
- 所有录音和编辑流程优先自动保存；中断后提供“继续上次讲述”。
- 错误文案不责备用户，避免“操作有误”；改为说明原因和解决办法。
- 破坏性操作必须二次确认，确认文案写清对象和后果，并提供易达的取消按钮。
- Toast 只承担“已保存”等短确认；需要用户处理的问题必须持续留在页面。
- 网络恢复后不自动覆盖用户离线内容；出现冲突时保留两个版本供确认。

推荐反馈示例：

| 场景 | 推荐文案 |
|---|---|
| 自动保存 | “已为您保存，可以放心继续讲” |
| 断网 | “网络暂时断开，刚才讲的内容已保存在本机” |
| 转写失败 | “这段录音还在，暂时没能整理成文字，可以稍后再试” |
| 麦克风权限关闭 | “还不能使用麦克风，您也可以先用文字记录” |
| 恢复内容 | “已找回上次讲到的地方” |

#### G. 家人协助

- 家属协助入口放在“我的”或相关详情页，不占据长辈讲述主路径。
- 明确当前操作身份，避免家属补充内容被误认为长辈本人讲述。
- 家属可协助上传照片、补充时间地点和校对文字，但不得无提示覆盖原始讲述。
- 涉及分享、删除、公开范围和人物形象替换时，必须让内容所有者明确确认。
- 家属远程协助完成后，长辈端用自然语言说明发生了什么。

#### H. 适老模式验收指标

- 开启和关闭适老模式均不超过 3 次点击，切换后当前页面立即生效。
- 切换模式前后的页面层级、内容和数据完全一致，不产生内容丢失或流程跳转。
- 从首页进入录音不超过 2 次点击。
- 首屏不滚动即可看到核心提问和录音入口。
- 关键流程全部可在不使用隐藏手势的情况下完成。
- 适老模式叠加 200% 系统字号时，允许滚动但不得出现文字截断、按钮重叠和无法触达的操作。
- 390px 宽度下，主操作位于单手拇指易达区且不被底栏遮挡。
- 断网、权限失败和处理中场景均能回答“内容是否还在”。
- 5 名目标年龄用户测试时，核心任务首次完成率目标 ≥80%；单次任务出现 2 人以上相同误解即进入修正清单。

### 6.3 通用可访问性

- 所有可点击元素提供 `focus-visible`，键盘焦点清楚可见。
- 图标按钮提供可读名称，状态变化可被辅助技术读取。
- 颜色之外增加文字、图标或形态线索。
- 图片提供等价说明；装饰图不进入阅读顺序。
- 支持系统字号放大时，按钮和卡片允许增高，文字不得截断。
- 遵循 `prefers-reduced-motion`，关闭非必要动画。

## 7. 禁用规则

1. 禁止整页大面积纯白或冷灰背景。
2. 禁止纯黑正文和低对比浅灰关键说明。
3. 禁止科技蓝紫、霓虹和玻璃发光作为品牌视觉。
4. 禁止同页出现多个同级高饱和陶土主按钮。
5. 禁止红色表达录音中、生成中等普通进度。
6. 禁止把所有模块都包成相同白色圆角卡片。
7. 禁止在书房展示未完成任务、强进度数字或重型整本书 Hero。
8. 禁止用隐藏手势替代可见入口。
9. 禁止引入未命名颜色、字号、圆角和阴影。
10. 禁止把原型试验别名或单页临时值直接升级为规范。
