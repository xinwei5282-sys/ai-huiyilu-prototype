# 云忆回忆录 UI 设计规范整理方案

## 1. 目标

将现有 `docs/UI设计规范.md` 从以配色说明为主的文档，整理为回忆录原型可长期复用、可直接指导设计与开发验收的 UI Design Foundation。

本次只整理 `/Users/xinwei/weiran-env/projects/ai-huiyilu-prototype`。小程序项目及其 `.claude/design-foundation.md` 不在本次范围内。

## 2. 真源与取舍规则

- 唯一规范真源继续使用 `docs/UI设计规范.md`，不建立平行规范。
- `prototype-v17.html` 是当前界面事实参考，用于核对已实现的颜色、字号、圆角、阴影、间距和组件表现。
- 原型里的临时样式、重复色值、页面试验和历史残留不自动升级为规范。
- 产品边界以 `AGENTS.md` 和已确认的项目规则为准；视觉表现不得覆盖产品边界。
- `docs/开发交付设计稿.md` 继续承担页面、状态和开发交付说明，不重复完整视觉规范。

## 3. 设计方向

### 3.1 核心气质

云忆回忆录面向长辈及其家人，界面应呈现：

- 温暖
- 安静
- 低压力
- 有陪伴感
- 有成果感

视觉意象以书页、相册、陶土、木色、暖光和家庭记忆为主。产品不能呈现为任务系统、管理后台、促销页面、冷科技产品或沉重的养老服务界面。

### 3.2 视觉骨架

- 暖奶油色承担大面积页面背景。
- 深棕色承担标题和正文，避免纯黑与低对比灰。
- 低饱和陶土色承担品牌强调、当前行动和进度。
- 松绿色只承担保存、完成、采纳和安心反馈。
- 红色只承担错误、危险和不可逆操作。
- 蓝灰色承担网络、权限和系统类中性信息。
- 纸页、书籍和相册材质用于建立记忆产品辨识度，但不能牺牲文字可读性。

## 4. 规范信息架构

正式规范整理为以下八部分：

1. 品牌定位与设计原则
2. Design Tokens
3. 排版、间距与布局
4. 图像、材质与图标语言
5. 核心组件规范
6. 关键页面模式
7. 状态、适老与无障碍规范
8. 禁用规则与渲染验收

### 4.1 Design Tokens

Tokens 至少覆盖：

- 基础背景、文字、品牌、状态和分割线颜色
- 字体栈、字号、行高与字重
- 4px 基础间距体系
- 页面边距和内容分组节奏
- 圆角等级
- 阴影等级
- 动效时长、缓动和减少动态效果策略
- 安全区和触控尺寸

已有 CSS 变量继续保留语义，但修正文档与 `prototype-v17.html` 不一致的值，并明确哪些变量允许新增、哪些仅为兼容别名。

### 4.2 图像与材质

- 首页照片使用自然暖光、真实家庭环境和克制景深，不使用棚拍宣传感或 AI 科技光效。
- 图片上的文字必须通过暖色遮罩或渐变保证可读。
- 书页材质使用轻微暖色、细线和浅阴影，不使用强拟物卷边或影响阅读的大纹理。
- 成果封面和章节书本可以增强书籍感，但信息层级优先于装饰。
- 图标采用简洁、易识别的线面结合风格，避免装饰性图标墙。

### 4.3 核心组件

重点规范以下组件的用途、尺寸、层级和状态：

- 主按钮、次按钮、文字按钮和危险按钮
- 录音主控、暂停、处理中和权限失败状态
- 顶部导航与底部三栏导航
- 故事成果卡、章节书本和整本书轻入口
- 状态标签、保存提示和错误提示
- 输入框、键盘输入区与照片上传
- 底部弹层、确认提示和空状态

组件不得全部退化为相同的白色圆角卡片。高频主操作、内容成果和系统反馈需要形成不同的视觉角色。

## 5. 页面模式与产品边界

### 5.1 讲述

- 一屏一焦点，突出“开口讲”。
- 录音控件位于拇指易达区，状态必须即时可见。
- 允许语音、键盘和照片切入，但次级入口不能抢主操作。
- 网络慢、权限失败、自动保存和内容恢复必须明确告知“内容没有丢”。

### 5.2 书房

- 书房只展示已完成成果。
- 章节成果是第一视觉单位。
- 整本书入口保持次级，不使用压住页面的重型 Hero 卡。
- 未完成、进行中和中断内容统一进入“我的”。

### 5.3 我的

- 承接未完成事项、账户信息和增强能力。
- AI 人物形象属于可选增强，不阻断讲述、成稿和分享。
- 危险操作远离高频主操作，并提供二次确认。

### 5.4 分享与成果

- 分享卡、人物形象和章节封面应引导回故事内容，而不是停留在单张图片生成。
- 分享结果保持真实、温暖和家庭记忆感，不做营销海报风。

## 6. 适老与无障碍底线

- 关键正文不小于 16px，长篇阅读和核心提问建议使用 18px 或更大字号。
- 辅助文字不小于 14px；更小字号只允许用于非关键角标或时间。
- 普通触控热区不小于 44px，高频主操作建议达到 56–60px。
- 文字与背景对比优先于“淡雅”效果。
- 不能仅依靠颜色区分状态，状态同时使用文字、图标或形态提示。
- 键盘不得遮挡输入区域，底部操作不得与系统手势区冲突。
- 加载、空、错误、断网、成功和恢复六类状态均需提供明确出口。
- 动效服务于状态变化，并提供 `prefers-reduced-motion` 降级。

## 7. 禁用规则

- 禁止大面积纯白或冷灰页面底色。
- 禁止使用科技蓝紫作为品牌主色。
- 禁止在同一页面堆叠多个高饱和陶土色主按钮。
- 禁止用红色表达普通进度。
- 禁止使用低对比浅灰承载关键说明。
- 禁止为了统一而把所有内容包进相同卡片。
- 禁止把未完成任务和强数字压力放进书房。
- 禁止引入未命名颜色、圆角、阴影或字号后不更新 tokens。
- 禁止只看代码即宣布 UI 规范已落地。

## 8. 整理实施边界

本轮正式整理只修改：

- `docs/UI设计规范.md`
- 必要时对 `docs/开发交付设计稿.md` 中与规范真源冲突的引用做最小校正

本轮不修改：

- `prototype-v17.html` 的页面结构和样式
- 小程序代码或小程序设计基础
- 产品流程、套餐、题库和业务文案
- Figma 或正式组件库

发现原型与规范不一致时，在规范中记录“当前实现差异”，不顺手改原型。

## 9. 验收标准

- 正式规范具备八部分结构，且不存在重复真源。
- 颜色、字号、圆角和阴影 token 与当前原型完成逐项对照。
- 关键组件都有用途、层级、尺寸和状态说明。
- 讲述、书房、我的、分享四类页面边界明确。
- 适老、触控、安全区、键盘避让和六类状态均有可执行规则。
- 文档不包含 `TBD`、`TODO`、小程序 KOC 设计语言或未经确认的新品牌方向。
- 文档修改通过 Markdown 内容检查和 `git diff --check`。
- 本轮若未修改原型，不把代码检查描述为真实 UI 已同步。
