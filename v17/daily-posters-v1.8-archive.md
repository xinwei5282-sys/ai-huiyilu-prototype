# 每日分享海报 PRD

版本：V1.8 · 更新：2026-11-17 · 产品：云忆 V17 回忆录

原型入口：`prototype-v17.html#daily-posters`。本文为每日分享海报的产品规则与提示词真源，覆盖旧版三列总览、偏好入口、换一张、多选及缩放方案。历史讨论见 [版本记录](daily-posters-history.md)，视觉规范见 [UI设计规范](../docs/UI设计规范.md)。

## 1. 产品目标与范围

### 1.1 解决的问题

面向希望分享问候、美景、生活感受和实用知识的长辈，减少找图片、写文案和选择设置的操作。默认参考回忆录已录入内容理解兴趣，但不要求先录入回忆，也不依赖每天新增回忆。

每天默认准备9张每日祝福；用户按需订阅其他类型后，以订阅内容替换部分祝福，合计仍为9张。每张具有不同主题、画面和表达，可独立分享。用户挑选单张查看、保存或主动分享，不自动发送朋友圈，不强制一次发九张。生成与展示均先仅用户可见。

### 1.2 本期边界

- 首页文字入口 → 按日期倒序的两列图片列表 → 同页图片浮层 → 单张保存或支持时的系统分享。
- 默认每日祝福、六类按需订阅、健康关注方向、专属笔名印章、空回忆兜底、默认参考回忆、低活跃调度、去重及内容审核。
- 海报为带文字的完整生成图片；前端不叠加或重排海报文字。界面按钮和日期分组标题使用正常UI文字。
- 生图复用视频生成平台的生图能力；本文不标注具体模型和价格。
- 不包含：多选、批量保存、用户手动换图、内容喜好页、少看这类、放大缩小、海报编辑器、自动代发和个体医疗诊断。
- 朋友圈配文仅作为后续内容元数据保留，本期无展示或复制入口。收藏和城市获取方式另行确认，不作为已有功能。五行、八字、八卦、黄历宜忌纳入“每日一卦”订阅，尚未实现。

### 1.3 当前原型与待开发能力

| 能力 | 当前状态 | 开发边界 |
|---|---|---|
| 首页入口、两列九图、同页浮层 | 已实现 | 入口无缩略图；列表不显示分类、营销介绍或重复标题 |
| 图片切换 | 已实现 | 手机左右滑动，桌面鼠标拖动；页码及箭头保留 |
| 单图保存、分享能力判断 | 已实现浏览器原型 | PNG下载；支持文件分享才展示分享按钮；不等于微信发布成功 |
| 多选、批量保存、缩放、预览标题栏 | 已移除 | 不再作为本期操作入口 |
| 跨日期分组与7天历史 | 本机原型已实现 | 实际打开产生日期组，倒序保留今天及前6日；未打开日期不补图；云端同步待接入 |
| 图片比例与像素 | 祝福样例已迁移 | 新九张祝福与PNG导出均720×1280、9:16；旧素材保留但不再用于当前列表 |
| 每日9张不同内容 | 当前有限图库 | 当前9张新祝福样例按日期轮换顺序，不能保证每天全新 |
| 每日祝福及六类订阅、健康关注方向、笔名印章 | 本机交互已实现，生成待接入 | 六类开关、健康方向、笔名本机保存；九张示例使用云山落款印章，尚不根据新笔名自动重绘，不冒充订阅内容已生成 |
| 默认参考回忆和个性化读取 | 待开发 | 当前不读取真实回忆做海报生成 |
| 平台生图、任务调度、云端去重、提醒 | 待开发 | 与视频生成复用平台，不等于当前原型已完成接入 |

### 1.4 本机状态逻辑（V1.7）

- 设置分为当前生效和待生效两份，每个日期组保存独立设置快照。今天已发布后修改订阅、健康方向或笔名，只改变下一日设置；原有生效订阅不会因编辑而被清空。今天尚未发布时，修改立即用于当天准备。
- 每类有效订阅占1张，其余每日祝福，总数9张；健康关注进入当日计划，未选择则通用健康。节日必须有核验数据才能占位，原型无节日源时不触发。暂无合格同类图时以同署名祝福兜底，不能把祝福标成已生成的健康、诗句或热点。
- 发布完整日期组后固定9张与顺序，刷新不会重排。列表只展示实际存在的日期，今天及前6日倒序排列，不补生成未打开日期。浏览浮层持有打开时日期快照；跨零点或其他窗口改设置不会换掉正在查看/保存的图片，关闭后更新列表。
- 笔名更改后，当前样例若不匹配则当天进入准备状态，仍能浏览历史。由于原型没有生图服务，这个状态不会自行完成；改回有合格样例的笔名后，尚未发布的当天可完成准备。原型只按样例笔名验证，不代表正式身份版本与印章资产核验已接入。
- 旧版本本机记录迁移为日期组，旧图片保留示例署名；设置写入失败回滚并提示。首次生成无法落盘时可临时浏览，提示只在本次可见。同一浏览器存储变更可同步列表；不承诺跨设备同步。
- “7天历史”在原型中仍是有限九张样例的日期记录，不代表每天生成新图；当前日期取本机时间。服务端时区、6点调度、低活跃暂停、真实内容供给/审核、生成重试、云端去重与提醒仍待接入。

## 2. 用户路径与页面要求

### 2.1 首页入口

名称“每日分享海报”，只保留标题与简短说明，不展示海报缩略图。点击进入当天所在的列表顶部；无需选择内容类型、填写资料或挑选生图参数。

默认参考用户已录入的回忆，无首次授权弹窗、同意/拒绝按钮或开启步骤。无回忆、读取失败或没有适合引用的内容时，直接展示完整通用九张，不要求补录。

### 2.2 按日期排列的海报列表

| 项目 | 规则 |
|---|---|
| 排序 | 以海报所属日期倒序，最新日期在最上方；不用生成完成时间排序 |
| 日期标题 | 每个日期组一个标题，如“11月17日”；跨年显示年份，避免歧义 |
| 当天 | 有当天分组则首先展示，进入列表默认定位顶部 |
| 历史 | 今天及前6个自然日内，实际准备且审核发布过的分组可见 |
| 缺失日期 | 直接跳过，不放空日期卡，不补生成未使用期间的历史 |
| 每日数量 | 正常完整发布9张独立海报，两个日期组不混排 |
| 布局 | 两列竖图、原始9:16比例，按组内固定顺序从左到右、从上到下；第9张左对齐，不拉伸占满两列 |
| 滚动 | 整个日期列表纵向滚动，日期组之间留出明显间距；无需切换日期页或日历选择器 |
| 控件 | 顶部返回与页面标题；日期与订阅、署名入口合并一行，图片组保持纯图片。无多选、喜好、换一张和分类标签 |
| 列表末尾 | 最后一个已有日期结束，不提示“补齐历史”，不无限生成内容 |

示例：11月17日有9张、16日有9张、15日无记录、14日有9张，则依次展示17日、16日、14日；15日不占位。日期窗口随当地自然日推进，超出窗口的日期移出列表。

### 2.3 当前页查看图片

- 点某张图片，在当前列表上打开深色浮层，不跳转新页面、不改变日期列表顺序。
- 直接展示完整图片，无顶部“海报预览”标题栏、分类和重复文案；关闭按钮独立位于右上角，保留可点击热区。
- 左滑看下一张、右滑看上一张，仅在打开时所属日期的9张内切换，不跨日期。延续原型循环方式：第9张左滑回到当天第1张，第1张右滑到当天第9张。
- 页码为“1 / 9”等，随当前图片更新；保留左右箭头作滑动替代。桌面可鼠标拖动图片切换。
- 纵向滚动、轻点或短距离移动不触发翻页；无放大、缩小、双击缩放和自定义双指缩放。
- 图片在可用宽高内等比例完整显示，不裁切、不需要上下滚动看完；小屏优先完整画面。关闭按钮位于图片外的独立热区，不能遮挡文字；翻图与保存并排，支持系统分享时操作区允许分行。
- 点击关闭、遮罩或Esc返回原列表位置与原图片焦点；重新从首页进入默认回到最新日期顶部。
- 浏览历史日期时不恢复多余标题栏；必要的回忆来源、健康原文、过期提醒位于图片下方，仅在相应条件下显示。

### 2.4 单张保存与分享

- 仅对当前查看的图片操作，删除多选、选择圆圈、批量保存栏及批量下载入口。
- 始终提供“保存图片”；仅当客户端支持图片分享时显示“分享图片”。浏览器不支持时隐藏分享，不提供无效按钮。
- 保存/分享与当前图片ID绑定。请求开始后锁定当前操作、防止重复提交，不因左右切换保存另一张；失败或取消后恢复操作。
- 保存使用完整原图，内容与预览一致，不带关闭按钮、页码、来源UI、平台标识或列表日期标题。原图已有来源文字保留。
- 浏览器下载仅反馈“已发起图片下载”；正式客户端依据真实保存结果反馈。系统分享取消留在原图，不当作发布成功。
- 微信朋友圈实际发布由用户完成。浏览器或系统分享回调不得统计成朋友圈发布成功。

## 3. 状态与异常处理

| 情况 | 用户看到的结果 | 系统处理 |
|---|---|---|
| 首次使用、回忆为空或无可用内容 | 当天通用9张，准备完成即可查看 | 优先已审核且身份匹配的库存，不等待补录或选兴趣；不足显示准备状态 |
| 当天个性化尚未完成 | 按订阅规则选取合格备用内容；无同类时用祝福补位 | 同日已发布组保持稳定，晚到结果用于后续合适日期，不突然替换已看图片 |
| 无足够合格当天成品 | 简短“今天的海报正在准备”及已有历史 | 不编造九张成功；补齐并审核后再发布完整分组 |
| 历史加载失败 | 当天和已加载日期仍可使用，提供重试 | 不清空已加载列表，不重新触发生图 |
| 某张图片加载失败 | 原位置保留图片加载失败及重试 | 重新取原资产，不以换图或重新生成代替加载重试 |
| 无网络 | 已缓存内容可看，未加载内容提示网络问题 | 不把网络失败记成不喜欢 |
| 刷新或多设备进入 | 同日期同一组、同顺序 | 服务端读取已发布记录，幂等创建 |
| 跨零点仍在看图 | 保持当前浮层，关闭后可刷新最新日期 | 不强制打断、不把旧日期图改为今天 |
| 当日日历数据缺失 | 当天可核实的日历信息，未知天气省略 | 没有可靠日期数据时不发布虚构日历，不拿昨日日期充数 |
| 历史日期/天气图片要保存或分享 | 提示所属日期及可能过期，由用户继续或取消 | 不自动更新原图内容 |
| 保存失败、分享取消 | 保留当前图片，可重试或继续浏览 | 不计成功、不重复生图 |
| 内容审核失败或发布后需下架 | 不再提供有问题图片的下载/分享 | 审核前用合格库存；发布后下架记录原因，安全替换或提示暂不可用 |
| 历史到期 | 从日期列表移出 | 不删除用户设备上的已下载图片 |

## 4. 默认内容与六类按需订阅

默认内容为“每日祝福”，无需选择或开启。未订阅其他类型时，每天9张均为祝福，分别使用晨间问候、平安牵挂、相聚期盼、顺遂祝愿等主题，结合山水、花草、小院和趣味画面；避免九张只换背景、重复同一句话。美景、兴趣趣味不再作为独立订阅类型。

| 类型 | 内容方向 | 个性化与触发 |
|---|---|---|
| 热点资讯 | 民生、社会、文化、科技等已核实资讯 | 按兴趣选题；不引用回忆证明新闻事实 |
| 每日健康 | 一张一个可靠健康知识点 | 可定制饮食营养、睡眠、运动、关节养护等关注方向；不推断诊断 |
| 每日一卦 | 卦象、卦意与生活启发，兼容五行、八字、八卦和黄历文化 | 订阅后参与推荐；个人八字仍需完整可靠的已有资料 |
| 怀旧往事 | 老物件、童年、家乡与真实往事 | 优先可用回忆；无合适素材用公共怀旧题材，不冒充用户经历 |
| 节日关怀 | 节日、节气问候与应景关怀 | 仅在经过核验的节日或节气当天参与推荐；普通日期回到每日祝福 |

| 每日诗句 | 经核验的古典诗词名句与意境画面 | 保留作者与作品名；笔名为分享落款，不冒充诗词作者 |

**本版编排默认值：**每个已订阅且当天有合格内容的类型占1张，其余名额为每日祝福；最多六类，因此至少保留3张祝福。未订阅为9张祝福；订阅健康和怀旧为7张祝福加各1张；六类订阅且当天为适用节日时为3张祝福加六类各1张。此分配为可调整的实现默认值，不增加每日总量，也不要求用户选择张数。

发布前按固定类型顺序安排：每日祝福、热点资讯、每日健康、每日一卦、怀旧往事、节日关怀、每日诗句；跳过未订阅或当天不适用类型。内容失效或没有合格同类库存时以合格每日祝福补足，不跨到未订阅类型，不把祝福标为健康或新闻。祝福库存仍不足则保留准备状态，不以重复或不合格内容凑数。

### 4.1 订阅与健康关注设置

- 订阅表示内容选择，本版不引入购买流程；收费与权益如需增加，应另行确定，不将“订阅”等同付费。
- 在列表日期组之外提供轻量“订阅内容”入口，进入六类开关；默认均关闭。它替代旧九类固定推荐，不恢复“喜好”“少看这类”或每张图设置。首次进入不弹选择框。
- 开启“每日健康”即可完成订阅，可选多个健康关注方向；不选择时使用通用健康主题。关注方向可随时修改，不要求填写疾病史。多个方向按近期曝光轮换，每张仅一个知识点。
- 开关自动保存并可取消，失败保留原值并提示重试，不假装保存成功。当天未发布时采用最新设置；当天已发布时从次日生效，显示简短生效提示，不替换已看图片。取消全部订阅后次日恢复9张祝福，历史已发布组保留。
- 订阅与通知分开：订阅不自动开启提醒，不改变超过7天未使用时的暂停规则。

### 4.2 五行、八字、八卦与黄历内容

五行、八字、八卦和黄历宜忌属于本期内容范围，不再列为默认排除项。归入“每日一卦”，仅在用户订阅后推荐，每天最多占1张。以卦象、卦意与生活启发为主，五行、八字和黄历作为相关文化选题；不要求补填出生资料。

| 方向 | 可生成内容 | 示例选题 |
|---|---|---|
| 五行 | 金木水火土的传统寓意、季节关联与生活文化；颜色搭配作为趣味参考 | “五行里的春天”“今日配色小趣味” |
| 八字 | 天干地支、生肖与干支文化；资料完整时可生成个人八字的传统解读 | “天干地支怎么读”“从八字看传统性格说法” |
| 八卦 | 卦象、自然意象、典故和处世启发 | “乾卦里的自强不息”“坤卦里的厚德载物” |
| 黄历宜忌 | 经核验的当日黄历信息与传统习俗提示 | “今日民俗小日历” |
| 日期信息 | 经核验的日期、星期和农历可作辅助信息；节气问候归节日关怀 | “今日民俗日期” |

**关联用户资料：**有完整、可靠且可用于此功能的已有出生资料时，才进入个人八字解读；出生日期、历法口径、出生时间及时区等所需字段须由程序校验。资料缺失、不确定或无法完成校验时，直接使用通用民俗题材，不从年龄、家乡或故事推测生日和时辰，不新增必填资料流程。普通回忆内容默认参考，不等于出生资料天然完整或准确。

**内容和表达：**以传统文化、民俗趣味及参考性解读呈现，须在该张图片角落标注“传统民俗·仅供参考”，不恢复界面顶部标题栏。个人解读不印具体出生日期、时辰、地点或完整四柱，避免用户随手分享时暴露详细个人资料。

**数据依据：**黄历、干支、排盘及五行分析所需结果由可核验的数据或计算模块提供，并记录采用口径与来源；生图模型只表达给定结果，不自行计算、杜撰“今日宜忌”或声称排盘准确。不同来源冲突时按统一选定口径处理，无法核验就换通用文化内容。

**边界：**不把民俗解读写成确定事实，不承诺转运、发财或转发获福，不制造灾祸恐吓；不以五行或八字给出治病、用药、投资等高风险行动建议。不因缺少资料或排盘失败阻塞当天九张。

**轮换与去重：**订阅后同一天只选一个主题；结合兴趣和近期记录轮换，不要求每天都有个人解读。通用题材按30天主题与文案去重；个人八字的基础信息不会每天变化，不能把同一解释换句话当成每日新内容。无合适内容时优先通用民俗，仍不合格则以每日祝福补位。

### 4.3 热点资讯

仅在用户订阅“热点资讯”后参与当天推荐，不再固定占第4张。与每日健康、节日关怀按用途区分，同组不重复选题。

- **内容选择：**优先民生热点、便民服务、文化体育、科技新鲜事，选择长辈容易理解、愿意与朋友交流的一件事。不为追逐热度选择未经核实的传闻或夸张标题。
- **时效：**优先最近24小时的报道；不足时可选近72小时且仍有价值的资讯。便民政策或活动以实际生效期、适用地区和活动时间为准，不能只看文章发布日期。旧闻不得改写为“刚刚”“今天发生”。
- **来源：**优先主管部门、事件主办方等原始发布或可靠新闻机构。程序提供原文链接、发布机构、发布时间、事件时间、适用地区和核验时间；转述稿应追溯原始来源，关键事实冲突未解决时不推荐。模型不得凭记忆补新闻。
- **图片文字：**一个事实清楚的标题，加2—3句重点，保留必要时间、地区与适用条件；图片内注明来源与报道日期。预览图片下方可打开原文，不恢复顶部标题栏。
- **配图：**采用示意插画、主题意象或可合法使用且来源明确的实际图片。AI示意图在图片内标明“示意图”，不得生成仿真新闻现场、人物发言或伪造新闻截图充当证据。
- **个人关联：**只参考兴趣挑选主题，不从家乡推测当前居住地。没有当前城市时推荐全国适用资讯；地方消息必须写清适用地区，不伪装成用户所在地消息。
- **无合适热点：**使用仍有效的便民生活资讯，不强行制造“热点”，不与当天每日健康重复。无可靠同类库存则以合格每日祝福补位。
- **更正与下架：**保存新闻来源及核验记录；收到可信更正或撤回信息后暂停原海报的保存和分享，核验后替换或下架，作为同日固定组的纠错例外。不能静默改写已下载图片。
- **历史使用：**列表历史仍按7天窗口。历史热点图保存或分享前提示报道日期；已过期的活动或政策资讯停止提供下载/分享，不只依赖“过期”提示继续传播。
- **去重：**同一事件没有实质新进展时不重复推荐；有新进展时核验后明确变化与时间，不把更换标题当新事件。

## 5. 默认参考回忆与引用范围

本功能默认参考回忆录已录入内容，不要求用户额外授权或主动开启。不增加授权弹窗、“同意，开始推荐”“先看通用海报”按钮或专属授权开关。默认参考只用于内容推荐与生成，不代表自动对外发送；每张图片仍由用户自行决定是否保存、分享。

- 默认利用已录入且可用的回忆理解兴趣，每日最多1张直接引用个人故事，仅在已订阅“怀旧往事”时使用；未订阅时不把个人故事混入祝福。热点资讯不直接引用个人回忆作为新闻内容。
- 无数据：完整九张通用精选；不要求先写回忆或填资料。
- 少量数据：优先提取兴趣，有合适、未重复素材才引用。
- 长期不更新：继续按兴趣、季节和当天信息生成；素材不足时回到公共内容，不改写同一故事硬凑。
- 不自动引用家庭矛盾、病史、财务等私密内容，不主动展示真实姓名、详细地址、联系方式。
- 不添加原记录里没有的时间、人物关系、对话或情节。本功能不包含个人照片使用或人脸重建。
- 直接引用的海报在预览页标注“来自你的回忆”，仅真实直接引用时在图片下方轻量展示，保留来源记录ID；标注不印在分享图上，不恢复顶部标题栏。
- 引用只使用生成时仍可用的记录，不使用已删除或不可读取的内容；无法取得有效来源时改用通用题材。

### 5.1 每个人的专属笔名与印章

- 每张成品包含稳定的个人笔名落款与对应印章，画面风格可变化，身份标识保持一致。印章为个人艺术章，不模仿官方公章、认证或专业资质。
- 优先使用用户已设置的笔名；没有时自动提供一个可修改的建议笔名并保存为海报署名，不要求首次填写。建议笔名不得冒充现有账号姓名，不从实名、出生信息或回忆中推断；用户可在“海报署名”设置修改笔名和确认印章预览，日常无需重复操作。
- 祝福和节日用“某某敬祝”，怀旧用“某某记”仅限真实个人回忆，公共怀旧用“某某分享”；健康、资讯、民俗、诗句使用“某某分享”。笔名不代表医学资质、新闻作者或古诗作者；引用诗句须保留真实作者与出处。
- 笔名、印文、印章参考资产统一存储并带版本。更改后用于下一次尚未发布的日期组；历史图片和设备已下载文件不自动修改。生成中旧版本结果不得覆盖新版本任务。
- 文字及印章均由生图直接形成完整图片，前端不叠加。稳定印章需要参考资产与成品核对，不能仅靠提示词宣称一致。印文错字、变形、串用他人署名或来源被遮挡均退回。
- 公共图库可复用选题与画面参考，带他人署名的成品不能直接复用；公共成品只有身份版本也匹配时才可直接交付。个性化尚未完成时使用该用户已审核且时效合格的库存，仍不足则显示准备状态，不以陌生署名凑九张。低活跃暂停专属生成时也遵守此规则。

### 5.2 热点资讯关注设置

开启热点资讯订阅后展开多选关注：民生政策、社会新闻、科技新知、文化文史、体育赛事、旅游见闻、乡村农业、国际动态。不选择或全部取消选择时默认综合资讯；关闭订阅保留关注方向，重新开启恢复。开关与选项自动保存，失败回滚，已发布后变更次日生效；当天未发布则按最新设置准备。

多个方向共同形成候选范围，不增加资讯张数；资讯仍占当日一个订阅名额，合格候选按时效、可信度、未重复程度选取，并避免长期只推荐一个方向。用户明确关注优先于回忆推断。无符合关注方向的合格资讯时，以同身份祝福兜底，不塞入未选方向。关注范围、报道来源和日期需传入内容生成与审核；标题和文学润色不得改变新闻事实，不为满足展示欲夸大事件或虚构用户关系。

当前原型已保存 newsTopics，写入当日计划，并筛选带对应主题标签的候选图；没有真实资讯源和资讯成品时仍用祝福样例。真实多主题排序、审核及生成待接入。关注设置不是开启消息通知。

## 6. 生成调度与历史保留

活跃度按用户成功打开每日海报列表或预览计，以账号当地自然日记录最近使用日期；不按单纯登录回忆录、后台预生成或通知送达计。

| 状态 | 生成与展示策略 |
|---|---|
| 首次使用 | 优先准备当天合格祝福9张；无需等待写回忆或选兴趣 |
| 近3天使用过海报 | 当地时间每天6点前准备当天9张；图库选取为主，必要时专属生成 |
| 连续4—7天未使用 | 暂停后台专属生成；打开时复用已发布组，尚未发布时恢复当天准备，按订阅和身份版本选库，必要时生成，不补历史 |
| 超过7天未使用 | 停止为该用户定时生成和主动提醒；返回时仅准备当天，不补历史 |

- 同一天固定一组，刷新、多设备登录不重复创建。回忆新录入优先用于次日，不重做当天已看过的整组。
- 本期无用户“换一张”入口，旧版每天3次手动换图规则作废。系统仅在发布前发现缺图、审核失败或失效时使用合格备用成品；刷新、滑动、保存不触发生图。已发布内容因安全问题下架时保留处置记录，允许安全替换，不覆盖已下载文件。
- 生成失败用已审核备用成品；日历不得以昨天的日期或天气顶替当天，天气不可用则省略。
- 提醒由用户主动开启，每天最多一次；生成完成不等于发送通知。超过7天未使用暂停，返回后不自动恢复通知。
- 列表保留今天及此前6个自然日的已发布分组，最多7组、63张；非最近7次使用日期。缺失日期不占位、不补生成。到期分组移出列表，用户已下载图片不受影响；当前无收藏入口，服务端原始资产清理周期另行确定。
- 历史日期/天气海报在保存或分享前提示“这是X月X日的海报，日期和天气可能已过期”，提供“继续保存/分享”“取消”；取消留在当前图片，不能静默修改原图日期。历史分组不作为当天日历的兜底。
- 生成任务按用户、当地日期和栏目幂等；通知、生成预算、活跃判定由程序执行，不交给提示词推断。

## 7. 健康内容来源与审核

流程：权威资料 → 专业内容审核入库 → 自动选题与忠实改写 → 完整带字图 → 核对文案/数字/来源 → 合格后推荐。不能仅凭AI自审即标为专业审核通过。

选题范围：饮食营养、日常活动、居家防跌倒、睡眠与心情、季节健康、健康信息辨别。一次只说一个知识点，保留适用条件。

- 仅使用审核通过且仍有效的知识条目，记录机构、原文链接、发布日期/复核日期、适用人群与必要限制。
- 禁止自行增加疗效、数字、偏方、用药方案、停药建议；不从回忆中的病史推断诊断或治疗。
- 图片内有简短来源，详情可查原文；来源由输入提供，不得编造机构背书。
- 无合格知识或生成审核失败时，换合格健康库存，仍无可用时以每日祝福补位，不用其他实用题材冒充健康。
- 生成后检查文字、数字、单位、条件、来源是否遗漏/错写；用户会选择发送不免除系统内容审核。

参考：[国家卫健委健康素养提升行动](https://www.nhc.gov.cn/xcs/c100123/202406/1b02d90b7f8a439181d1800af1f44989.shtml)、[中国疾控中心健康科普信息生成与传播指南](https://www.chinacdc.cn/jkyj/yyyjk2/jswj13949/201508/t20150812_296899.html)。

## 8. 去重与行为反馈

对照最近30天的主题、核心句、画面构图、引用故事ID和具体细节。同一故事只换措辞仍算重复，不把模型自述“不重复”视为通过；程序保留记录并检查。九张内部也检查用途和画面重复。

不选不等于不喜欢。记录查看、保存请求、保存结果、系统分享请求和结果；本期无喜欢、少推荐、多选或换图入口，不为这些动作设计前台埋点；下载、复制、系统分享回调不等于朋友圈发布成功。生成与推送失败均不记为已使用内容。

## 9. 生图平台与任务交付

### 9.1 平台复用原则

**使用与微电影视频生成相同的平台提供海报生图能力，不新建一套独立生成平台。** 复用项目已有的服务端接入方式、任务查询及结果接收机制；海报使用独立业务任务类型，避免与视频任务混淆。产品界面不展示平台名称、模型选择或价格参数。

当前项目原型尚未接入每日自动生图，平台复用为已确认的后续接入要求。本PRD不指定模型及价格，也不将平台返回任务ID视为生成成功。

### 9.2 从策划到发布

1. 调度服务根据当地日期、活跃度及可用回忆，先检查当天已发布组和未完成任务。
2. 策划程序按订阅和九张分配规则选取合格库存；仅缺少合适成品时安排生图。日期、新闻事实与时效、健康知识和回忆事实先核验。
3. 服务端将整张带字海报提示词及必要且已筛选的回忆事实提交给视频生成平台的生图能力；不发送完整回忆库和无关资料。
4. 保存平台任务ID，按平台已支持方式接收完成通知或查询终态；页面关闭不会新建任务，重新进入读取同一任务。
5. 成功后获取原图并转存到业务可控资产存储，确认可读取、比例正确、文字完整；平台临时链接不直接当长期历史资产。
6. 完成文字、事实、来源、隐私、日期和重复性检查。平台成功但审核未通过，仍不得推荐。
7. 单张合格后进入可用图库；当天九张齐备并通过组内去重后，发布固定的九张日期组。

### 9.3 状态与失败规则

任务状态建议：`待提交 → 排队/生成中 → 待审核 → 可用`；失败、超时、审核不通过分别记录，日期组有“待准备 / 已发布 / 下架”状态。任务状态用于后台处理，不在长辈页面暴露技术日志。

- 重复打开、刷新、保存或翻图不重复提交。提交超时但结果未知时先按任务标识查询，确认终态后再处理，避免重复生成。
- 重复回调幂等处理；过期任务、旧版本任务不能覆盖已发布组；平台图片生成完成不直接发通知。
- 单张失败优先用同栏已审核库存兜底；同一任务不得无限重试。重试上限和超时阈值由服务端统一配置，失败原因可追溯。
- 公共库存不足或平台不可用时保留可用历史，明确当天准备状态。日期日历的时效校验不能因兜底跳过。
- 发布前复核回忆来源是否仍有效；已删除或不可读取的来源不再进入新推荐，在途任务改用通用内容兜底。
- 凭据只放服务端，前端不携带平台密钥。记录平台任务与业务海报的对应关系，图片失败可定位到任务和审核原因。

### 10.1 分类文案与文学质量

共同要求：文字须匹配内容类型和画面，表达具体、自然、有节奏，长辈一读就懂；通常标题4—12字、正文1—2句，必要事实和适用条件优先于字数。祝福、诗意类优先一到两行核心表达，避免为填版面加长文案；标题可以弱于核心祝福，不统一套大字标题。每张只表达一个核心意思，不堆砌“岁月静好、时光温柔、美好如期而至”等空泛套话，不强行押韵，不说教，不诱导转发。文学性通过生活细节、意象和情感体现，不以生僻词替代质量。

| 类型 | 写作要求 | 表达参考或结构 |
|---|---|---|
| 每日祝福 | 有问候对象与具体祝愿，亲切舒展，不预测运势 | “晨光入窗，清茶在手。愿你今日，身闲心也闲。” |
| 热点资讯 | 准确简练，先说发生什么，再说与生活的关系；不诗化事实 | 已核实事件标题＋关键事实＋必要时间地区＋来源日期 |
| 每日健康 | 温和清楚，一次一个知识点；必要条件完整，不拿顺口溜替代依据 | 生活场景标题＋经审核建议＋适用限制＋来源 |
| 每日一卦 | 卦象意象与生活启发衔接，有传统韵味但不故作玄虚 | 核验卦名与卦意＋适度生活启发＋民俗参考标注 |
| 怀旧往事 | 用物件、动作与场景承载情绪；个人细节必须有来源 | 公共题材：“搬一条板凳，等一场露天电影。银幕还没亮，笑声已坐满了场。” |
| 每日诗句 | 精选适合分享的诗句，核对原句、作者、作品名；不编造古诗，不把解释混作原文 | 原句＋真实作者与作品名＋个人分享落款；无可靠出处时用祝福补位 |
| 节日关怀 | 贴合当天节俗、节气与关系，不默认家庭团圆或亲人健在 | 中秋通用示例：“一轮月，照着远近的人。愿今夜的牵挂，都有温柔的回音。” |

以上示例用于语气标尺，不作为每日固定句库。引用诗词必须核对原句、作者与出处；无法确认则不用引用，不伪造古诗名言。怀旧示例无个人来源时不得写成“我当年”。健康和资讯先审核事实再润色，润色后复核语义是否改变。九张祝福也须在对象、祝愿、意象和句式上有差异，不以同义词替换规避去重。

| 资产存储与历史 | 后端 | 已发布组稳定，7天列表窗口与资产清理分离 |
| 保存和分享 | 客户端/测试 | 按真实运行环境判断能力与反馈 |

主要风险与处理：生图错字→逐字核对并退回；画面同质化→组内及30天去重；回忆重复/隐私→最多一张且可追溯；平台失败→库存兜底；用户长期不使用→停止专属调度；历史时效误导→保存前提醒。

2. 多日期数据联调：本机排序、7天窗口与跨日期浏览已实现；继续接入云端真实日期组、历史时效提醒及网络异常状态。
3. 生成闭环：库存、默认回忆参考、内容策划、平台生图、审核、去重、调度及通知。
4. 上线前验收：实际客户端/微信能力、平台真实任务终态和内容审核共同通过，再安排试运行；具体排期由开发评估。
