# 每日分享海报 PRD

版本：V1.2 · 更新：2026-11-17 · 产品：云忆 V17 回忆录

原型入口：`prototype-v17.html#daily-posters`。本文为每日分享海报的产品规则与提示词真源，覆盖旧版三列总览、偏好入口、换一张、多选及缩放方案。历史讨论见 [版本记录](daily-posters-history.md)，视觉规范见 [UI设计规范](../docs/UI设计规范.md)。

## 1. 产品目标与范围

### 1.1 解决的问题

面向希望分享问候、美景、生活感受和实用知识的长辈，减少找图片、写文案和选择设置的操作。默认参考回忆录已录入内容理解兴趣，但不要求先录入回忆，也不依赖每天新增回忆。

每天准备9张用途不同、可独立分享的完整海报。用户挑选单张查看、保存或主动分享，不自动发送朋友圈，不强制一次发九张。生成与展示均先仅用户可见。

### 1.2 本期边界

- 首页文字入口 → 按日期倒序的两列图片列表 → 同页图片浮层 → 单张保存或支持时的系统分享。
- 每日九栏内容、空回忆兜底、默认参考回忆、低活跃调度、去重及内容审核。
- 海报为带文字的完整生成图片；前端不叠加或重排海报文字。界面按钮和日期分组标题使用正常UI文字。
- 生图复用视频生成平台的生图能力；本文不标注具体模型和价格。
- 不包含：多选、批量保存、用户手动换图、内容喜好页、少看这类、放大缩小、海报编辑器、自动代发、个体医疗诊断和运势预测。
- 朋友圈配文仅作为后续内容元数据保留，本期无展示或复制入口。收藏、黄历宜忌和城市获取方式另行确认，不作为已有功能。

### 1.3 当前原型与待开发能力

| 能力 | 当前状态 | 开发边界 |
|---|---|---|
| 首页入口、两列九图、同页浮层 | 已实现 | 入口无缩略图；列表不显示分类、营销介绍或重复标题 |
| 图片切换 | 已实现 | 手机左右滑动，桌面鼠标拖动；页码及箭头保留 |
| 单图保存、分享能力判断 | 已实现浏览器原型 | PNG下载；支持文件分享才展示分享按钮；不等于微信发布成功 |
| 多选、批量保存、缩放、预览标题栏 | 已移除 | 不再作为本期操作入口 |
| 跨日期分组与7天历史 | 待开发 | 当前只保存当天一组，不冒充已有历史 |
| 图片比例与像素 | 新规格待素材迁移 | 目标9:16、720×1280；现有样例为3:4，旧导出900×1200，须重新生成素材并同步布局/导出，不算已达标 |
| 每日9张不同内容 | 当前有限图库 | 现有11张带字成品按本地日期选取，不能保证每天全新 |
| 九栏内容、健康审核、日期天气 | 规则已明确，待接入 | 当前样例不代表九栏完整落地 |
| 默认参考回忆和个性化读取 | 待开发 | 当前不读取真实回忆做海报生成 |
| 平台生图、任务调度、云端去重、提醒 | 待开发 | 与视频生成复用平台，不等于当前原型已完成接入 |

## 2. 用户路径与页面要求

### 2.1 首页入口

名称“每日分享海报”，只保留标题与简短说明，不展示海报缩略图。点击进入当天所在的列表顶部；无需选择内容类型、填写资料或挑选生图参数。

默认参考用户已录入的回忆，无首次授权弹窗、同意/拒绝按钮或开启步骤。无回忆、读取失败或没有适合引用的内容时，直接展示完整通用九张，不要求补录。

### 2.2 按日期排列的海报列表

| 项目 | 规则 |
|---|---|
| 排序 | 以海报所属日期倒序，最新日期在最上方；不用生成完成时间排序 |
| 日期标题 | 每个日期组一个标题，如“11月17日”；跨年显示年份，避免歧义 |
| 当天 | 有当天分组则首先展示，进入列表默认定位顶部 |
| 历史 | 今天及前6个自然日内，实际准备且审核发布过的分组可见 |
| 缺失日期 | 直接跳过，不放空日期卡，不补生成未使用期间的历史 |
| 每日数量 | 正常完整发布9张独立海报，两个日期组不混排 |
| 布局 | 两列竖图、原始9:16比例，按组内固定顺序从左到右、从上到下；第9张左对齐，不拉伸占满两列 |
| 滚动 | 整个日期列表纵向滚动，日期组之间留出明显间距；无需切换日期页或日历选择器 |
| 控件 | 顶部返回与页面标题；组内只有日期和图片。无多选、喜好、换一张和分类标签 |
| 列表末尾 | 最后一个已有日期结束，不提示“补齐历史”，不无限生成内容 |

示例：11月17日有9张、16日有9张、15日无记录、14日有9张，则依次展示17日、16日、14日；15日不占位。日期窗口随当地自然日推进，超出窗口的日期移出列表。

### 2.3 当前页查看图片

- 点某张图片，在当前列表上打开深色浮层，不跳转新页面、不改变日期列表顺序。
- 直接展示完整图片，无顶部“海报预览”标题栏、分类和重复文案；关闭按钮独立位于右上角，保留可点击热区。
- 左滑看下一张、右滑看上一张，仅在打开时所属日期的9张内切换，不跨日期。延续原型循环方式：第9张左滑回到当天第1张，第1张右滑到当天第9张。
- 页码为“1 / 9”等，随当前图片更新；保留左右箭头作滑动替代。桌面可鼠标拖动图片切换。
- 纵向滚动、轻点或短距离移动不触发翻页；无放大、缩小、双击缩放和自定义双指缩放。
- 图片宽度充分利用浮层空间，保持比例、不裁切海报文字；小屏内容超高时图片区可滚动，底部操作保持可见。
- 点击关闭、遮罩或Esc返回原列表位置与原图片焦点；重新从首页进入默认回到最新日期顶部。
- 浏览历史日期时不恢复多余标题栏；必要的回忆来源、健康原文、过期提醒位于图片下方，仅在相应条件下显示。

### 2.4 单张保存与分享

- 仅对当前查看的图片操作，删除多选、选择圆圈、批量保存栏及批量下载入口。
- 始终提供“保存图片”；仅当客户端支持图片分享时显示“分享图片”。浏览器不支持时隐藏分享，不提供无效按钮。
- 保存/分享与当前图片ID绑定。请求开始后锁定当前操作、防止重复提交，不因左右切换保存另一张；失败或取消后恢复操作。
- 保存使用完整原图，内容与预览一致，不带关闭按钮、页码、来源UI、平台标识或列表日期标题。原图已有来源文字保留。
- 浏览器下载仅反馈“已发起图片下载”；正式客户端依据真实保存结果反馈。系统分享取消留在原图，不当作发布成功。
- 微信朋友圈实际发布由用户完成。浏览器或系统分享回调不得统计成朋友圈发布成功。

## 3. 状态与异常处理

| 情况 | 用户看到的结果 | 系统处理 |
|---|---|---|
| 首次使用、回忆为空或无可用内容 | 当天通用9张，可立即查看 | 优先已审核公共库存，不等待补录或选兴趣 |
| 当天个性化尚未完成 | 当天合格公共9张 | 同日已发布组保持稳定，晚到结果用于后续合适日期，不突然替换已看图片 |
| 无足够合格当天成品 | 简短“今天的海报正在准备”及已有历史 | 不编造九张成功；补齐并审核后再发布完整分组 |
| 历史加载失败 | 当天和已加载日期仍可使用，提供重试 | 不清空已加载列表，不重新触发生图 |
| 某张图片加载失败 | 原位置保留图片加载失败及重试 | 重新取原资产，不以换图或重新生成代替加载重试 |
| 无网络 | 已缓存内容可看，未加载内容提示网络问题 | 不把网络失败记成不喜欢 |
| 刷新或多设备进入 | 同日期同一组、同顺序 | 服务端读取已发布记录，幂等创建 |
| 跨零点仍在看图 | 保持当前浮层，关闭后可刷新最新日期 | 不强制打断、不把旧日期图改为今天 |
| 当日日历数据缺失 | 当天可核实的日历信息，未知天气省略 | 没有可靠日期数据时不发布虚构日历，不拿昨日日期充数 |
| 历史日期/天气图片要保存或分享 | 提示所属日期及可能过期，由用户继续或取消 | 不自动更新原图内容 |
| 保存失败、分享取消 | 保留当前图片，可重试或继续浏览 | 不计成功、不重复生图 |
| 内容审核失败或发布后需下架 | 不再提供有问题图片的下载/分享 | 审核前用合格库存；发布后下架记录原因，安全替换或提示暂不可用 |
| 历史到期 | 从日期列表移出 | 不删除用户设备上的已下载图片 |

## 4. 每日九张内容定义

| 位置 | 栏目 | 生成方向 | 回忆使用方式 |
|---|---|---|---|
| 1 | 早安问候 | 当季晨光、花草、小院，简短自然的打招呼 | 通常不需要 |
| 2 | 吉祥祝福 | 柿子、喜鹊等吉祥题材，朴素祝福；不承诺转运 | 通常不需要 |
| 3 | 美景欣赏 | 山水、花草、田园；送一幅好风景，不伪装用户实拍 | 可参考兴趣与家乡风物，不称真实旧照或亲历 |
| 4 | 生活心情 | 自在、知足、热爱生活，具体口语化表达 | 可引用真实生活态度 |
| 5 | 亲情友情 | 牵挂、感谢、陪伴、期待相聚，不施加回应压力 | 可引用温暖细节；未知家庭情况不假设配偶、子女 |
| 6 | 健康与实用分享 | 一张一个实用知识点 | 按兴趣选题，不依据病史生成个人医疗建议 |
| 7 | 怀旧共鸣 | 老物件、童年、家乡、旧时生活 | 最适合引用真实往事；无数据用公共怀旧题材 |
| 8 | 兴趣趣味 | 茶、花、饭、散步、动物小幽默，兼顾诗词等兴趣 | 偶尔引用真实趣事；不编造用户经历 |
| 9 | 今日生活日历 | 日期、星期、农历、节气；有当前城市才加天气 | 不依赖回忆，不从家乡猜当前城市 |

九张须用途不同，不全部变成风景加平安祝福。每张可独立分享，不印栏目编号、大幅品牌或期数。兴趣趣味不拿年龄、疾病、家庭矛盾开玩笑。

健康栏试运行比例：每周4天健康、2天生活技巧、1天防骗；根据使用情况调整，不要求每次九张里再增加健康卡。

## 5. 默认参考回忆与引用范围

本功能默认参考回忆录已录入内容，不要求用户额外授权或主动开启。不增加授权弹窗、“同意，开始推荐”“先看通用海报”按钮或专属授权开关。默认参考只用于内容推荐与生成，不代表自动对外发送；每张图片仍由用户自行决定是否保存、分享。

- 默认利用已录入且可用的回忆理解兴趣，每日最多1张直接引用个人故事，优先第4、5、7栏，第8栏偶尔使用。
- 无数据：完整九张通用精选；不要求先写回忆或填资料。
- 少量数据：优先提取兴趣，有合适、未重复素材才引用。
- 长期不更新：继续按兴趣、季节和当天信息生成；素材不足时回到公共内容，不改写同一故事硬凑。
- 不自动引用家庭矛盾、病史、财务等私密内容，不主动展示真实姓名、详细地址、联系方式。
- 不添加原记录里没有的时间、人物关系、对话或情节。本功能不包含个人照片使用或人脸重建。
- 直接引用的海报在预览页标注“来自你的回忆”，仅真实直接引用时在图片下方轻量展示，保留来源记录ID；标注不印在分享图上，不恢复顶部标题栏。
- 引用只使用生成时仍可用的记录，不使用已删除或不可读取的内容；无法取得有效来源时改用通用题材。

## 6. 生成调度与历史保留

活跃度按“使用每日海报”计，不按单纯登录回忆录计。

| 状态 | 生成与展示策略 |
|---|---|
| 首次使用 | 立即展示当天公共精选9张；无需等待写回忆或选兴趣 |
| 近3天使用过海报 | 当地时间每天6点前准备当天9张；图库选取为主，必要时专属生成 |
| 连续4—7天未使用 | 暂停专属生成，使用当天公共精选；打开时按偏好补充或替换 |
| 超过7天未使用 | 停止为该用户定时生成和主动提醒；返回时仅准备当天，不补历史 |

- 同一天固定一组，刷新、多设备登录不重复创建。回忆新录入优先用于次日，不重做当天已看过的整组。
- 本期无用户“换一张”入口，旧版每天3次手动换图规则作废。系统仅在发布前发现缺图、审核失败或失效时使用合格备用成品；刷新、滑动、保存不触发生图。已发布内容因安全问题下架时保留处置记录，允许安全替换，不覆盖已下载文件。
- 生成失败用已审核备用成品；日历不得以昨天的日期或天气顶替当天，天气不可用则省略。
- 提醒由用户主动开启，每天最多一次；生成完成不等于发送通知。超过7天未使用暂停，返回后不自动恢复通知。
- 列表保留今天及此前6个自然日的已发布分组，最多7组、63张；非最近7次使用日期。缺失日期不占位、不补生成。到期分组移出列表，用户已下载图片不受影响；当前无收藏入口，服务端原始资产清理周期另行确定。
- 历史日期/天气海报在保存或分享前提示“这是X月X日的海报，日期和天气可能已过期”，提供“继续保存/分享”“取消”；取消留在当前图片，不能静默修改原图日期。历史分组不作为当天日历的兜底。
- 生成任务按用户、当地日期和栏目幂等；通知、生成预算、活跃判定由程序执行，不交给提示词推断。

## 7. 健康内容来源与审核

流程：权威资料 → 专业内容审核入库 → 自动选题与忠实改写 → 完整带字图 → 核对文案/数字/来源 → 合格后推荐。不能仅凭AI自审即标为专业审核通过。

选题范围：饮食营养、日常活动、居家防跌倒、睡眠与心情、季节健康、健康信息辨别。一次只说一个知识点，保留适用条件。

- 仅使用审核通过且仍有效的知识条目，记录机构、原文链接、发布日期/复核日期、适用人群与必要限制。
- 禁止自行增加疗效、数字、偏方、用药方案、停药建议；不从回忆中的病史推断诊断或治疗。
- 图片内有简短来源，详情可查原文；来源由输入提供，不得编造机构背书。
- 无合格知识或生成审核失败时，换合格库存或非健康实用题材，不强制满足周配比。
- 生成后检查文字、数字、单位、条件、来源是否遗漏/错写；用户会选择发送不免除系统内容审核。

参考：[国家卫健委健康素养提升行动](https://www.nhc.gov.cn/xcs/c100123/202406/1b02d90b7f8a439181d1800af1f44989.shtml)、[中国疾控中心健康科普信息生成与传播指南](https://www.chinacdc.cn/jkyj/yyyjk2/jswj13949/201508/t20150812_296899.html)。

## 8. 去重与行为反馈

对照最近30天的主题、核心句、画面构图、引用故事ID和具体细节。同一故事只换措辞仍算重复，不把模型自述“不重复”视为通过；程序保留记录并检查。九张内部也检查用途和画面重复。

不选不等于不喜欢。记录查看、保存请求、保存结果、系统分享请求和结果；本期无喜欢、少推荐、多选或换图入口，不为这些动作设计前台埋点；下载、复制、系统分享回调不等于朋友圈发布成功。生成与推送失败均不记为已使用内容。

## 9. 生图平台与任务交付

### 9.1 平台复用原则

**使用与微电影视频生成相同的平台提供海报生图能力，不新建一套独立生成平台。** 复用项目已有的服务端接入方式、任务查询及结果接收机制；海报使用独立业务任务类型，避免与视频任务混淆。产品界面不展示平台名称、模型选择或价格参数。

当前项目原型尚未接入每日自动生图，平台复用为已确认的后续接入要求。本PRD不指定模型及价格，也不将平台返回任务ID视为生成成功。

### 9.2 从策划到发布

1. 调度服务根据当地日期、活跃度及可用回忆，先检查当天已发布组和未完成任务。
2. 策划程序按九栏选取合格库存；仅缺少合适成品时安排生图。日期、健康知识和回忆事实先核验。
3. 服务端将整张带字海报提示词及必要且已筛选的回忆事实提交给视频生成平台的生图能力；不发送完整回忆库和无关资料。
4. 保存平台任务ID，按平台已支持方式接收完成通知或查询终态；页面关闭不会新建任务，重新进入读取同一任务。
5. 成功后获取原图并转存到业务可控资产存储，确认可读取、比例正确、文字完整；平台临时链接不直接当长期历史资产。
6. 完成文字、事实、来源、隐私、日期和重复性检查。平台成功但审核未通过，仍不得推荐。
7. 单张合格后进入可用图库；当天九栏齐备并通过组内去重后，发布固定的九张日期组。

### 9.3 状态与失败规则

任务状态建议：`待提交 → 排队/生成中 → 待审核 → 可用`；失败、超时、审核不通过分别记录，日期组有“待准备 / 已发布 / 下架”状态。任务状态用于后台处理，不在长辈页面暴露技术日志。

- 重复打开、刷新、保存或翻图不重复提交。提交超时但结果未知时先按任务标识查询，确认终态后再处理，避免重复生成。
- 重复回调幂等处理；过期任务、旧版本任务不能覆盖已发布组；平台图片生成完成不直接发通知。
- 单张失败优先用同栏已审核库存兜底；同一任务不得无限重试。重试上限和超时阈值由服务端统一配置，失败原因可追溯。
- 公共库存不足或平台不可用时保留可用历史，明确当天准备状态。日期日历的时效校验不能因兜底跳过。
- 发布前复核回忆来源是否仍有效；已删除或不可读取的来源不再进入新推荐，在途任务改用通用内容兜底。
- 凭据只放服务端，前端不携带平台密钥。记录平台任务与业务海报的对应关系，图片失败可定位到任务和审核原因。


### 11.1 图片交付规格

- 标准成品为 **720×1280像素、9:16竖版**；本期不采用480档，也不要求1080档。
- 列表、浮层及保存均使用同一完整画面。缩略图可等比例缩小，但不得拉伸或裁掉文字；保存必须取得720×1280标准成品。
- 生图端按9:16构图。若平台返回更高像素的同一比例图片，可等比例缩至720×1280；不把低清图放大冒充达标成品。
- 返回比例不符时重生成，不能通过拉伸或直接裁切现有3:4样例凑规格。图中文字由生成过程产生，缩放后仍需核对可读性。
- 单张保存交付PNG；缩略图可采用压缩格式，不得将低清缩略图作为下载原图。
- 当前原型3:4样例和900×1200导出属于旧规格，待下一轮重新生成9:16素材后同步列表比例、预览及导出。仅更新本PRD不代表素材已迁移。

## 12. 生成结果检查

先校验成品宽720、高1280及9:16比例，再逐字对照策划文本，检查错字、漏字、数字/单位/来源错误、文字遮挡、裁切和对比度；检查图文一致、回忆事实一致、私密信息、日期天气有效性。失败不进入推荐；重试预算用尽则用合格备用成品。OCR仅辅助，健康审核须有内容专业审核环节。

## 14. 指标、依赖与交付阶段

### 14.1 指标口径

无线上基线，不编造增长目标；上线试运行后以真实数据确定目标。首次上线至少记录：入口访问→列表到达→图片查看→保存请求/实际成功（有可靠回执时）→系统分享请求/结果。按海报ID和所属日期关联。

重点观察：海报查看用户占列表访问用户比例、单图保存请求率、实际保存成功率（限可观测客户端）、次日/7日再次使用率、当天9张及时可用率、生成失败率、审核退回率、重复率和每个活跃用户的新生成任务数。分享意图不等同真实朋友圈发布。

### 14.2 依赖与职责

| 依赖 | 责任角色 | 交付条件 |
|---|---|---|
| 视频生成平台生图能力 | 后端/平台接入 | 提交、终态、回传、原图访问及任务追踪联通 |
| 默认参考回忆及可分享事实 | 产品/后端 | 无额外开启操作；来源可查；无数据通用兜底 |
| 健康与实用知识库 | 内容/专业审核 | 有效来源、适用条件及审核记录 |
| 日期、农历、节气、天气 | 后端/数据接入 | 可核验、含时区，未知天气省略 |
| 资产存储与历史 | 后端 | 已发布组稳定，7天列表窗口与资产清理分离 |
| 保存和分享 | 客户端/测试 | 按真实运行环境判断能力与反馈 |

主要风险与处理：生图错字→逐字核对并退回；画面同质化→组内及30天去重；回忆重复/隐私→最多一张且可追溯；平台失败→库存兜底；用户长期不使用→停止专属调度；历史时效误导→保存前提醒。

### 14.3 交付阶段

1. 原型规则对齐：完成单图浏览与最新删除项，本文明确多日期及平台接入边界。
2. 多日期数据联调：真实日期组、排序、7天窗口、滚动恢复、历史提醒及异常状态。
3. 生成闭环：库存、默认回忆参考、内容策划、平台生图、审核、去重、调度及通知。
4. 上线前验收：实际客户端/微信能力、平台真实任务终态和内容审核共同通过，再安排试运行；具体排期由开发评估。
